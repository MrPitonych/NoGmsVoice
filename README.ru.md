# NoGmsVoice

[In English](README.md)

Офлайн-распознавание речи, русской или английской, для Android TV без сервисов Google.

NoGmsVoice - это служба распознавания речи Android (`android.speech.RecognitionService`) на библиотеке
[Vosk](https://alphacephei.com/vosk/) с малой моделью Vosk внутри APK. Есть две сборки: `ru` с русской
моделью и `en` с моделью американского английского. Когда служба назначена системным распознавателем,
кнопка микрофона должна заработать в любом приложении, которое пользуется стандартным
`SpeechRecognizer`; подтверждено в Lampa, Зоне и TizenTube Cobalt (клиент YouTube). Ничего не уходит с
телевизора: нет разрешения на интернет, нет аккаунтов, нет телеметрии. Из разрешений, которые выдаются
вручную, ей нужен только микрофон.

Написана для китайской версии Xiaomi TV (S55 Mini LED 2024, MiTV-MFTR0, Android 11): её родной помощник
понимает только китайский, а распознаватель Google на неё не поставить. Рассчитана на ARM-телевизоры и
приставки на Android 8.0 или новее, у которых нет своего распознавателя. Пока проверена на двух ТВ
Xiaomi; см. [Проверено на](#проверено-на).

## Что умеет и чего нет

- **Работает:** микрофон внутри приложений, которые используют `SpeechRecognizer`. Подтверждено в Lampa,
  Зоне и TizenTube Cobalt. Текст появляется по ходу речи (в приложениях, которые его запрашивают),
  индикатор громкости в приложении двигается.
- **Один язык на сборку.** В сборке `ru` модель `vosk-model-small-ru-0.22`, в сборке `en` -
  `vosk-model-small-en-us-0.15`. Язык, который просит приложение, не учитывается: ставьте нужную сборку.
- **Не помощник.** Нажатие голосовой кнопки на пульте само по себе ничего не запускает: сначала нажмите
  на значок микрофона в приложении. Активации по ключевому слову нет.
- **Пока не поддерживаются** приложения, которые вместо службы запускают экран `RECOGNIZE_SPEECH`. Они
  пишут «нет приложения» или не реагируют.
- **Качество** такое, как у малых моделей Vosk: нормально для коротких поисковых фраз, хуже для длинной
  диктовки, а имена и иностранные названия, которых нет в словаре модели, распознаются неверно. Доля
  ошибочных слов (WER) по данным авторов моделей: у русской 11,8% на краудсорсинговых записях, 21,3% на
  дальнем микрофоне и 22,7% на аудиокнигах; у английской 9,9% на LibriSpeech test-clean и 10,4% на
  TED-LIUM. На ТВ пока использовалась только русская модель.

## Проверено на

- **Xiaomi TV S55 Mini LED 2024** (MiTV-MFTR0), китайская прошивка V816.0.16.0.RFTMATV, Android 11,
  32-битный ARM, родной Bluetooth-пульт с микрофоном: сборка `ru` с источником звука по умолчанию.
- **Xiaomi L55MA-SPL**, китайская прошивка, Android 11, 32-битный ARM, Bluetooth-пульт MiRC: сборка `ru` с
  [источником звука](#если-не-работает) `mic`, потому что с источника по умолчанию там приходит тишина
  ([#1](https://github.com/MrPitonych/NoGmsVoice/issues/1)).

На обоих ТВ помощник Xiaomi (`com.xiaomi.voicecontrol`) был отключён, с включённым не проверялось. Сборка
`en` - тот же код с английской моделью, на устройстве она пока не проверялась.

На этих ТВ микрофон пульта передаёт звук, только пока зажата голосовая кнопка, поэтому: нажмите на значок
микрофона в приложении, зажмите кнопку на пульте, скажите фразу, отпустите. Конец потока служба считает
концом фразы.

Не проверено: USB-микрофоны, другие пульты, модели Xiaomi 2025 года со встроенными микрофонами, другие
марки. Работает на вашем ТВ или нет, напишите в issue: модель ТВ, версию прошивки и
[лог](#если-не-работает). IP-адреса, имена сетей Wi-Fi и серийные номера не указывайте.

## Установка

Что нужно:

- ARM-телевизор или приставка на Android 8.0 или новее. В выводе `adb shell getprop ro.product.cpu.abilist`
  должно быть `armeabi-v7a`, иначе установка закончится ошибкой `INSTALL_FAILED_NO_MATCHING_ABIS`.
- Микрофон: пульт с микрофоном или USB-микрофон.
- Около 150 МБ свободного места (для сборки `en` 125 МБ): APK плюс распакованная модель.
- Компьютер с ADB в той же сети ([platform-tools](https://developer.android.com/tools/releases/platform-tools)).
  На Xiaomi: Settings → Accounts and Security → ADB debugging (на прошивке S55 отладка выключается при
  каждой перезагрузке; настройки ниже перезагрузку переживают). На других ТВ: параметры разработчика (семь
  нажатий на номер сборки), затем отладка по USB или по сети. Первый `adb connect` просит подтверждение на
  экране ТВ.

Шаги:

1. Скачайте `NoGmsVoice-<версия>-ru.apk` или `NoGmsVoice-<версия>-en.apk` из
   [Releases](https://github.com/MrPitonych/NoGmsVoice/releases) и сверьте SHA-256 с указанным в описании
   релиза (`sha256sum <файл>` в Linux, `shasum -a 256 <файл>` в macOS, `certutil -hashfile <файл> SHA256`
   в Windows).
2. Запомните, что ТВ использует сейчас, чтобы вернуть это при удалении (на S55 пусто):

   ```
   adb connect <ip телевизора>
   adb shell settings get secure voice_recognition_service
   ```

   Если там `com.google.android.katniss`, это приложение заберёт настройку обратно: см. «Настройка
   возвращается сама» в разделе [Если не работает](#если-не-работает).

3. Установите APK, выдайте доступ к микрофону и назначьте службу системным распознавателем:

   ```
   adb install -r NoGmsVoice-<версия>-ru.apk
   adb shell pm grant io.github.mrpitonych.nogmsvoice android.permission.RECORD_AUDIO
   adb shell settings put secure voice_recognition_service io.github.mrpitonych.nogmsvoice/.VoskRecognitionService
   adb shell am broadcast -n io.github.mrpitonych.nogmsvoice/.WarmupReceiver
   ```

Значка нет: это фоновая служба, в списке приложений ничего не появится. Последняя строка необязательна:
она распаковывает и загружает модель сразу, а не при первом запросе, и завершается, когда модель готова,
но не позже чем через 10 с (тогда модель догружается в фоне). Дальше первый запрос после запуска процесса
службы (после перезагрузки или после того, как Android выгрузил её за бездействием) длится на несколько
секунд дольше, пока грузится модель; на Xiaomi это 3-5 с. Сказанное за это время не теряется и
распознаётся, когда модель готова.

Чтобы сменить язык, поставьте так же другую сборку: она заменит установленную, разрешение и настройка
останутся. APK с другой подписью не встанет поверх установленного (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`):
релиз с GitHub поверх собранного самостоятельно, самостоятельная сборка поверх релиза, артефакт CI поверх
любого из них. Сначала удалите старый (`adb uninstall io.github.mrpitonych.nogmsvoice`), установите новый и
снова выполните три строки `adb shell` (удаление отзывает разрешение и может сбросить настройку).

## Как пользоваться

В приложении нажмите на значок микрофона. С пультом Xiaomi: в течение 8 с зажмите голосовую кнопку,
скажите фразу, отпустите. Пауза в пару секунд при зажатой кнопке тоже заканчивает фразу. На ТВ, где
микрофон слушает постоянно, просто говорите: фраза заканчивается через пару секунд после последнего слова
или не позже чем через 20 с. Такой сценарий предусмотрен в коде, но на таком ТВ ещё не проверялся.

## Если не работает

```
adb shell logcat -d -v time NoGmsVoice:V VoskAPI:W AndroidRuntime:E '*:S'
```

В логе виден весь путь запроса, включая распознанный текст:

| Строка | Значение |
|---|---|
| `listening for uid N, source S` (с `, partial results wanted`, если приложение просит промежуточный текст) | приложение запросило распознавание; S - источник звука, см. ниже |
| `model unpacked in N ms` | первая загрузка после каждой установки или обновления: файлы модели скопированы из APK |
| `model loaded in N ms` | каждый запуск процесса службы (после перезагрузки или после выгрузки за бездействием) |
| `model load failed` | дальше причина; приложение получает `ERROR_SERVER` |
| `warmup: model ready`, `warmup: model still loading`, `warmup: model failed to load` | чем закончился прогрев |
| `audio started N ms after the request` | пришёл первый фрагмент звука с микрофона |
| `decoding N ms captured while the model loaded` | первый запрос после запуска процесса: речь, записанная до готовности модели |
| `no audio: the microphone sent nothing` | за 8 с ничего не пришло. С пультом Xiaomi: голосовая кнопка не была зажата |
| `no speech in N ms of audio` | звук шёл, но слов в нём не было |
| `stream stopped after N ms of audio` | кнопку на пульте отпустили: фраза закончена |
| `silence after N ms of audio` | после последних слов больше ничего не сказано: фраза закончена |
| `utterance cap reached` | 20 с звука: фраза обрезана |
| `stop requested` | приложение само завершило фразу |
| `cancelled` | приложение отменило запрос (результата не получает) |
| `capture silenced by the system` | ТВ отдаёт этому приложению тишину вместо звука с этого источника: см. «Источник звука» ниже |
| `result: "..."` | что получило приложение; пусто значит `ERROR_NO_MATCH` |

Ошибки, которые видит приложение: `ERROR_AUDIO` (микрофон не открылся или перестал отдавать звук:
выполнен ли `pm grant`?), `ERROR_SPEECH_TIMEOUT` (нет звука или нет слов), `ERROR_NO_MATCH` (ничего не
распознано), `ERROR_SERVER` (не загрузилась модель: смотрите лог). `ERROR_INSUFFICIENT_PERMISSIONS`
значит, что у самого приложения нет разрешения на микрофон:
`adb shell pm grant <пакет приложения> android.permission.RECORD_AUDIO`.

Проверить настройку и список распознавателей, известных системе:

```
adb shell settings get secure voice_recognition_service
adb shell cmd package query-services --brief -a android.speech.RecognitionService
```

**Настройка возвращается сама.** Скорее всего, её забрал помощник ТВ; задайте её снова. Помощник Google для
ТВ, `com.google.android.katniss`, забирает её, пока это приложение включено. Если его отключить, настройка
держится, в том числе после перезагрузки ([#1](https://github.com/MrPitonych/NoGmsVoice/issues/1)):

```
adb shell pm disable-user --user 0 com.google.android.katniss
adb shell settings put secure voice_recognition_service io.github.mrpitonych.nogmsvoice/.VoskRecognitionService
```

**Источник звука.** Микрофон открывается через источник Android `VOICE_RECOGNITION`: именно туда ТВ
направляют звук с голосового пульта. Некоторые прошивки отдают приоритет на этом источнике другому
приложению, а всем остальным подсовывают тишину: поток идёт, в логе `capture silenced by the system`,
результаты пустые (так было на Xiaomi L55MA-SPL из [Проверено на](#проверено-на), там работает `mic`).
Источник меняется глобальной настройкой; первым стоит попробовать `mic`:

```
adb shell settings put global nogmsvoice_audio_source mic
adb shell settings delete global nogmsvoice_audio_source      # обратно к voice_recognition
```

Допустимые значения: `voice_recognition` (по умолчанию), `mic`, `default`, `camcorder`, `unprocessed`,
`voice_communication`. Новое значение действует со следующего запроса; строка лога
`listening for uid N, source S` показывает, какой источник используется.

## Удаление

```
adb shell settings delete secure voice_recognition_service
adb uninstall io.github.mrpitonych.nogmsvoice
```

Если до установки в настройке было значение, верните его через `settings put` вместо удаления. Если
отключали `com.google.android.katniss`, включите его снова: `adb shell pm enable com.google.android.katniss`.

## Сборка из исходников

Нужны JDK 17 и Android SDK с platform 34 и build-tools 34.0.0 (переменная `ANDROID_HOME` или
`local.properties` с `sdk.dir`). Скрипту `fetch-model.sh` нужны `sh`, `curl` и `unzip`: в Windows
запускайте его из Git Bash или WSL, а собирайте через `gradlew.bat`.

```
./fetch-model.sh all                    # или ru, или en: скачивает модели (40-45 МБ каждая) и сверяет md5
./gradlew lintRuRelease lintEnRelease assembleRelease
```

APK лежат в `app/build/outputs/apk/<язык>/release/NoGmsVoice-<версия>-<язык>.apk`, по 45-50 МБ. Без
`keystore.properties` (см. `keystore.properties.example`) они подписываются отладочным ключом, для своего
ТВ этого достаточно. GitHub Actions собирает обе сборки и прогоняет для них lint так же при каждом push в
`main`, для тегов и для каждого pull request, а если APK запрашивает что-то кроме двух разрешений ниже,
сборка падает.

Почему сделано так:

- `QUERY_ALL_PACKAGES`: Android 11 (проверено на нём; по документации новые версии ведут себя так же)
  проверяет разрешение на микрофон у вызывающего приложения через распознаватель, поэтому распознаватель
  должен видеть все приложения. Без этого любое приложение получает `ERROR_INSUFFICIENT_PERMISSIONS`.
- Нет разрешения `INTERNET`: в этом смысл проекта.
- Только `armeabi-v7a`: 32-битный код ARM работает на большинстве ARM-телевизоров и приставок, включая
  64-битные (Xiaomi только 32-битный); остальные архитектуры добавили бы к APK около 10 МБ.
- Без R8 (сжатия кода): JNA находит классы Vosk через рефлексию.
- Одна модель на сборку вместо выбора в приложении: нет кода загрузки, нет разрешения на интернет, и APK
  работает с первого запроса. Ещё один язык - это третья сборка (`productFlavors`) в `app/build.gradle` со
  своей строкой assets, своими строками `service_label`, своей строкой в `fetch-model.sh` и своей задачей
  lint в workflow.
- Другая модель для языка: её имя и md5 (из `model-list.json` Alpha Cephei) в `fetch-model.sh`, который
  при следующем запуске заменит старые файлы, плюс имя модели и цифры качества в этом файле. Копия,
  распакованная на ТВ, при следующей установке заменяется автоматически.
